# 리미터(soft clip) 비교 샘플 (#20)

MusicGen 출력 중 peak가 1.0을 넘는 세 곡(30초, 로컬 MPS 생성, float32로 저장한 원본)을 두 방식으로 PCM 16bit 저장한 결과입니다.

- `*_limited.wav`: `audio_output.save_output_wav` (기준 0.9 soft clip → PCM16)
- `*_hardclip.wav`: 기존 방식처럼 1.0에서 잘라서 PCM16 저장

## 수치
| 곡 | 원본 peak | 1.0 초과 샘플 | 리미터가 바꾼 샘플(>0.9) | 최대치(≥0.999)에 붙은 샘플 (limited / hardclip) | 전체 RMS 변화 (limited) |
|---|---|---|---|---|---|
| `humix_test_5_loop` | 1.774 | 482개 (0.05%), 230회, 최장 0.38ms | 1,879개 (0.20%) | 91 / 487 | -0.008 dB |
| `humix_test_6_two_stage` | 1.503 | 195개 (0.02%), 135회, 최장 0.22ms | 1,235개 (0.13%) | 16 / 197 | -0.004 dB |
| `humix_test_2_extended_range` | 1.150 | 57개 (0.006%), 25회, 최장 0.19ms | 472개 (0.05%) | 0 / 59 | -0.0005 dB |

`humix_test_5_loop`에서 두 파일 간 0.001 이상 차이 나는 샘플은 1,132개(0.12%)이고, 최대 차이는 0.024입니다.

## 정리
- 0.9 이하 샘플은 그대로이고(16bit 양자화 오차만 있음), 곡 전체 음량은 사실상 변하지 않음
- 0.9~1.1 근처 값에서는 리미터가 부드럽게 눌러 줌. 청취 시 차이는 작지만 리미터 쪽이 약간 더 부드럽게 들림
- 조금만 넘는 곡(`humix_test_2_extended_range`)은 리미터 적용 후 최대치에 붙은 샘플이 없음
- 1.3 이상처럼 크게 넘은 피크는 두 방식 모두 최대치 근처로 납작해짐 → 피크 모양까지 살리려면 이슈의 대안(고정 배율 후 리미터)이 필요하며, 서버 GPU 출력의 peak 분포를 보고 결정
